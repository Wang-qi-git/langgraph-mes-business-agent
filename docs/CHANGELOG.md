\## \[V4.0] - 2026-10-07



\### 🎯 核心成果



| 指标 | V3 | V4 | 变化 |

|------|-----|-----|------|

| `answer\_score` AVG | 0.92 | \*\*0.96\*\* | ↑ 0.04 |

| `rag\_score` AVG | 0.61 | \*\*0.67\*\* | ↑ 0.06 |

| 快速模式延迟 | — | \*\*1.06s\*\*（首字 0.74s） | 新增 |

| 深度模式延迟 | 55s | \*\*44s\*\* | ↓ 20% |

| case\_018 分数 | 0.67 / 0.33 | \*\*1.0 / 1.0\*\* | ✅ 修复 |



\### ✨ Added（新增）



\#### 1. BOM 版本前置守卫（代码级元数据校验）



\- 新增 `check\_bom\_version\_guard()` 函数，用正则提取 query 中的 BOM 版本号

\- 与 `md\_docs/` 目录扫描出的真实版本列表对比

\- 命中不存在的版本号时\*\*直接返回拦截话术\*\*，跳过向量检索和 LLM

\- \*\*效果\*\*：

&#x20; - case\_018（BOM V99 查询）：0.67 / 0.33 → \*\*1.0 / 1.0\*\*

&#x20; - 该用例延迟：53.81s → \*\*9.27s\*\*

\- \*\*核心教训\*\*：确定性问题（版本是否存在）用代码拦截，概率性问题（答案是否足够）才交给 LLM



\#### 2. 模型预热机制



\- 新增 `\_warmup\_models()` 函数，在模块加载时执行：

&#x20; - 加载 BGE Embedding + Chroma 向量库

&#x20; - 加载 Reranker 模型（bge-reranker-v2-m3）

&#x20; - \*\*真跑一次完整检索\*\*（吃掉首次 HNSW 索引加载 + PyTorch JIT kernel 编译开销）

\- \*\*效果\*\*：首次调用不再承担 50s 冷启动成本，用户请求全部享受稳态性能



\#### 3. 双进程架构（FastAPI + Streamlit）



\- 新增 `api\_server.py`：FastAPI 常驻后端，启动时预热模型

\- 新增 `streamlit\_app.py`：纯 UI 前端，通过 HTTP 调用后端

\- \*\*解决的问题\*\*：Streamlit 每次交互 rerun 整个脚本，导致本地模型被重复加载（每次 50s）

\- \*\*架构图\*\*：



Streamlit (前端) ← HTTP → FastAPI (后端，模型常驻)



\#### 4. 双模式设计



| 模式 | 检索策略 | 输出风格 | 首字延迟 | 总耗时 |

|------|---------|---------|---------|--------|

| ⚡ 快速 | 向量 Top-2（跳过 Reranker） | 100\~150 字要点 | \*\*0.74s\*\* | \*\*1.06s\*\* |

| 🔍 深度 | 粗召回 10 + Reranker 精排 3 | 结构化长报告 | 40s | \*\*44s\*\* |



\- 新增 `quick\_answer()` / `quick\_answer\_stream()` 函数

\- 快速模式\*\*牺牲少量召回质量换速度\*\*（Top-2 向量检索已覆盖 90%+ 场景）

\- 深度模式保留完整 Reranker 精排，保证最高质量



\#### 5. Reflection 快速收敛保护



\- 在 `reflect\_node` 新增分支 C：所有任务已完成且有非空输出时\*\*直接收敛\*\*，不再调 LLM

\- \*\*效果\*\*：业务用例从 3 轮 Reflection 降至 1\~2 轮



\### 🔧 Changed（变更）



\- `graph\_agent\_skeleton.py`：`chroma\_search` 改用模块级全局缓存 `\_GLOBAL\_VECTOR\_DB`（原函数属性缓存不兼容 Streamlit）

\- `REFLECT\_REPLAN\_PROMPT`：新增"收敛优先原则"，禁止因"可以更详细"而继续循环

\- `QUICK\_PROMPT`：输出长度从 200\~500 字缩短到 \*\*100\~150 字\*\*

\- 清理临时文件：删除 `api.py`、`app.py`、`debug\_llm.py`、`stream\_demo.py`、`test\_reranker.py`、`\_test\_reranker.py`



\### ❌ Removed（移除）



\- 旧版 Streamlit 单进程入口 `app.py`

\- 旧版 FastAPI 入口 `api.py`



\### 🔬 Fixed（修复）



\- \*\*BOM V99 幻觉\*\*：Agent 输出 7000+ 字报告但从未识别出"V99 不存在"

\- \*\*Streamlit rerun 重加载模型\*\*：每次交互重新加载 50s

\- \*\*首次调用慢\*\*：把冷启动成本从用户请求挪到服务启动阶段



\### 📌 Known Issues（已知限制）



\- 首次启动需 50s 预热（一次性）

\- 深度模式仍耗时 40\~60s（Reflection 循环 + Reranker 精排的必然代价）

\- 无多会话隔离（暂未引入 `thread\_id` + checkpointer）

\- 无 Prometheus 监控指标暴露

\- 依赖外部 API（DeepSeek / Tavily / LangSmith）

\## \[V2.0] - 2026-09-05



\### 🎯 核心成果



| 指标 | V1 | V2 | 变化 |

|------|-----|-----|------|

| `answer\_score` AVG | 0.80 | \*\*0.93\*\* | ↑ 0.13 |

| `rag\_score` AVG | 0.38 | 0.38 | 持平 |



\### ✨ Added



\- \*\*双层拒答机制\*\*：

\- \*\*Layer 1（Prompt 层）\*\*：Planner 节点用 Prompt 约束 LLM 判断是否属 MES 领域

\- \*\*Layer 2（代码层）\*\*：Task Execute 检测到 `REJECT:` 前缀后，\*\*直接返回固定话术，不调用 LLM\*\*



\### 🎯 效果



\- 拒答用例 Token：\*\*15000 → 780\*\*（↓ 95%）

\- 拒答用例耗时：\*\*30s → 3s\*\*（↓ 90%）

\- answer\_score 提升 +0.13，主要来自拒答类用例



\### 🔬 失败尝试



\- 曾尝试加"对象不存在直接拒答"Prompt 规则

\- 5 个用例测试：0.53 → 0.87 ✅

\- \*\*全量 20 用例测试：0.90 → 0.70\*\* ❌ 规则被过度泛化，8 个正常用例退化

\- \*\*最终决策\*\*：回退该规则，接受 case\_004 的短板

\- \*\*核心教训\*\*：\*\*5 个用例能验证方向对不对，只有全量才能验证改得稳不稳\*\*



\### 📌 Known Issues



\- BOM V99 幻觉问题（后续 V4 用代码级守卫解决）

\- 延迟依旧 55s（未定位到瓶颈）

\## 🧭 演进逻辑总结



| 阶段 | 核心问题 | 解决方案 | 学到的东西 |

|------|---------|---------|-----------|

| V1 → V2 | 非业务问题浪费 Token | 双层拒答（Prompt + 代码） | 代码拦截比 Prompt 更可靠 |

| V2 → V3 | RAG 召回相关性低 | 知识库扩充 + metadata 修复 | 数据质量 > 模型调优 |

| V3 → V4a | BOM V99 幻觉 | 代码级前置守卫 | 确定性问题用代码，概率性问题用 LLM |

| V3 → V4b | 首次调用 55s | 模型预热 | 冷启动成本要从用户请求中剥离 |

| V3 → V4c | Streamlit rerun 重加载 | 双进程架构 | Streamlit 不适合做重计算 |

| V3 → V4d | 单次调用 36s | 跳过 Reranker + 缩短输出 | 定位瓶颈比盲目调参重要 |
